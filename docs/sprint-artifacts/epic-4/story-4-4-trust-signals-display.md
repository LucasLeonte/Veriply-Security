## Story

As an End-user,  
I want to see whether an answer is verified or AI-generated,  
so that I know how much to trust it.

## Acceptance Criteria

### Verified KB Badge

1. **Given** an answer came from the Verified Knowledge Base  
   **When** I see the response in the chat  
   **Then** I see a green "✓ Verified" badge near the top of the response  
   **And** the badge has light green background: #DCFCE7  
   **And** the text is dark green: #166534

2. **Given** I hover over the "✓ Verified" badge  
   **When** I see the tooltip  
   **Then** it displays: "This answer has been verified by a human expert"  
   **And** optionally shows: "Updated: [date]"

### AI-Generated Badge

3. **Given** an answer was generated by the RAG pipeline (not from Verified KB)  
   **When** I see the response in the chat  
   **Then** I see an amber "AI Generated" badge  
   **And** the badge has light amber background: #FEF3C7  
   **And** the text is dark amber: #92400E

4. **Given** I hover over the "AI Generated" badge  
   **When** I see the tooltip  
   **Then** it displays: "This answer was generated by AI from our knowledge base"  
   **And** it shows confidence level: "Confidence: 85%"

### Low-Confidence Pending Verification

5. **Given** an answer has low confidence (< configured threshold, typically 80%)  
   **When** the confidence score is calculated  
   **Then** the response is NOT sent to the user immediately  
   **And** instead they see a message:

    ```
    "I'm checking with the team.
     You'll receive a verified response shortly."
    ```

6. **Given** the response is pending verification  
   **When** the agent reviews and approves it  
   **Then** a notification appears in the user's chat:
    ```
    "✓ We have an answer for you!"
    ```
    **And** the verified response appears in the chat  
    **And** it displays the "✓ Verified" badge

### Confidence Score Display

7. **Given** a user requests an answer  
   **When** response is generated  
   **Then** the confidence score (0-100%) is calculated but NOT shown in chat UI  
   **And** confidence is used internally for routing (high → user, low → HITL queue)

8. **Given** a response has confidence 85-100%  
   **When** displayed in chat  
   **Then** it shows "✓ Verified" or "AI Generated" badge (no percentage)  
   **And** user sees it as trusted information

### Visual Hierarchy

9. **Given** a chat message has multiple components  
   **When** I look at the response  
   **Then** I see (top to bottom):

    - Message content (large, readable)
    - Citations (inline and/or footnotes)
    - Badge (✓ Verified or AI Generated)
    - Feedback icons (thumbs up/down)

10. **Given** multiple responses in the chat  
    **When** I scroll through the conversation  
    **Then** badges are consistent in style and placement  
    **And** different badge types are clearly distinguishable

### Accessibility

11. **Given** I'm using a screen reader  
    **When** I encounter a response badge  
    **Then** the screen reader announces: "Verified, this answer has been verified by a human expert"  
    **Or**: "AI Generated, this answer was generated by AI"

12. **Given** I'm on a low-vision setting  
    **When** I see badge colors  
    **Then** colors meet WCAG AA contrast standards (4.5:1 ratio)

### Edge Cases

13. **Given** a response is being generated (streaming)  
    **When** tokens are arriving  
    **Then** the badge is NOT shown until generation is complete  
    **And** a "Generating..." placeholder appears

14. **Given** a response errors before completion  
    **When** the error is displayed  
    **Then** NO badge is shown  
    **And** error message takes precedence

15. **Given** confidence score is exactly at the threshold (e.g., 80% threshold)  
    **When** score = 80%  
    **Then** it's treated as high-confidence → shown to user with badge  
    **And** routing decision: >= threshold → user, < threshold → HITL

## Dev Notes

### Architecture Patterns

-   **Trust Indicators**: Visual badges signal answer source and verification status
-   **Lazy Verification**: Low-confidence answers route to HITL without blocking user
-   **Status Polling**: Frontend polls for verification completion (simple, no WebSocket needed)
-   **Composable Trust**: Trust level determined by source (Verified KB vs RAG) + confidence

### Component Reuse

-   **From Story 4.1**: Reuse ChatWindow, ChatMessage structure
-   **From Epic 3.4**: Reuse ConfidenceScoringService for score calculation
-   **From Epic 5**: Integration with HITL queue for pending verification

### Security & Privacy

-   **Score Not Leaked**: Confidence score not shown in UI (internal only)
-   **Source Attribution**: Verified KB answers attributed correctly (via badge)
-   **User Trust**: Clear signals help users calibrate trust in responses

### Learnings from Previous Stories

From Story 4.1 (Chat Interface) [Source: epic-4/story-4-1-web-chat-interface.md]:
